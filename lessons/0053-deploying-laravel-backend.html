Lesson 0053: Deploying Laravel Backend

Alamin ang iba't ibang paraan ng pag-deploy ng Laravel app — mula VPS hanggang Laravel Forge.

Lesson Goal Maunawaan ang deployment options para sa Laravel (VPS, shared hosting, Forge), makapag-setup ng Nginx at PHP-FPM, at makagawa ng CI/CD pipeline gamit ang GitHub Actions.

Deployment Options para sa Laravel

Option Pros Cons Best for
VPS (DigitalOcean, Linode) Full control, mura Manual setup, server maintenance Developers na may sysadmin experience
Shared Hosting (Hostinger, SiteGround) Mura, madali Limited control, may restrictions Small projects, beginners
Laravel Forge Automated server management, push-to-deploy May monthly fee ($12+/month) Seryosong Laravel developers
Platform as a Service (Ploi, Heroku) Madali i-setup, scalable Mas mahal, vendor lock-in Teams na gusto ng simplicity

"Ang Laravel Forge ay parang personal assistant para sa server management — pero mahal. Kung tipid, manual VPS setup."

Server Setup: Nginx, PHP-FPM, MySQL

Para sa manual VPS setup, narito ang basic steps:

1

I-install ang Nginx:

sudo apt update
sudo apt install nginx -y
2

I-install ang PHP at extensions:

sudo apt install php8.2-fpm php8.2-mysql php8.2-xml \
  php8.2-mbstring php8.2-curl php8.2-bcmath -y
3

I-configure ang Nginx server block:

server {
    listen 80;
    server_name example.com;
    root /var/www/myapp/public;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    index index.php;

    charset utf-8;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    error_page 404 /index.php;

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
4

I-install at i-configure ang MySQL:

sudo apt install mysql-server -y
sudo mysql_secure_installation

CI/CD Basics: GitHub Actions para sa Laravel

Ang GitHub Actions ay nag-a-automate ng testing at deployment sa tuwing mag-push ka ng code.

# .github/workflows/deploy.yml
name: Deploy Laravel

on:
  push:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ALLOW_EMPTY_PASSWORD: yes
          MYSQL_DATABASE: testing
        ports:
          - 3306:3306
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: 8.2
          extensions: mbstring, pdo_mysql
      - run: composer install --no-interaction
      - run: cp .env.example .env
      - run: php artisan key:generate
      - run: php artisan migrate --force
      - run: php artisan test

  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to server
        uses: appleboy/ssh-action@v1.0.0
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /var/www/myapp
            git pull origin main
            composer install --no-dev --optimize-autoloader
            php artisan migrate --force
            php artisan config:cache
            php artisan route:cache
            php artisan view:cache
            php artisan queue:restart

Summary

  • May apat na deployment options: VPS, shared hosting, Laravel Forge, at PaaS.
  • Ang Forge ang pinaka-convenient pero may bayad; ang VPS ay mas mura pero manual setup.
  • Kailangan ng Nginx, PHP-FPM, at MySQL para sa server setup.
  • Ang GitHub Actions ay nag-a-automate ng testing at deployment.
  • Gamitin ang AI para mag-generate ng deployment scripts at server configuration.
