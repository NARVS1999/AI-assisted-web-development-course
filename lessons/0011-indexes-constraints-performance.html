Lesson 0011: Indexes, Constraints & Performance

Alamin kung paano pabilisin ang iyong queries gamit ang indexes at maunawaan ang mga constraints para sa data integrity.

Lesson Goal Makapag-explain kung ano ang indexes at kung kailan ito gagamitin, makapag-apply ng constraints (primary key, foreign key, unique), at makagamit ng EXPLAIN para i-optimize ang queries.

Database Constraints

Ang constraints ay rules na nag-eenforce ng data integrity sa iyong database.

Constraint Purpose Example
PRIMARY KEY Unique identifier ng bawat row id INT PRIMARY KEY
FOREIGN KEY Nag-uugnay ng dalawang tables FOREIGN KEY (user_id) REFERENCES users(id)
UNIQUE Tinitiyak na unique ang value sa column email VARCHAR(100) UNIQUE
NOT NULL Hindi pwedeng walang value name VARCHAR(100) NOT NULL
DEFAULT Default value kapag walang ibinigay status VARCHAR(20) DEFAULT 'active'
CHECK Validates values based sa condition CHECK (age >= 18) 
-- Example: Table na may maraming constraints
CREATE TABLE employees (
    id INT AUTO_INCREMENT PRIMARY KEY,
    employee_code VARCHAR(20) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    full_name VARCHAR(200) NOT NULL,
    department_id INT,
    salary DECIMAL(10, 2) CHECK (salary > 0),
    status VARCHAR(20) DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (department_id) REFERENCES departments(id)
);

Indexes: Bakit Kailangan?

Ang index parang table of contents ng libro — kung wala, isa-isang babasahin ni MySQL bawat pahina (row) para mahanap ang hinahanap mo. Ito ay tinatawag na full table scan.

Paano Gumagana ang B-Tree Index

Ang default index type sa MySQL ay B-Tree (Balanced Tree). Ini-oorganisa nito ang data sa tree structure para ang paghahanap ay logarithmic time (O(log n)) imbes na linear (O(n)).

-- Walang index: kung may 1M rows, isa-isang titingnan lahat
SELECT * FROM users WHERE email = 'juan@example.com';
-- Possible na umabot ng ilang segundo

-- May index: diretso sa tamang location
CREATE INDEX idx_email ON users(email);
-- Ngayon, logarithmic search lang — milliseconds lang

Types of Indexes

Index Type Gamit Syntax
Single-column Isang column lang CREATE INDEX idx_name ON table(col);
Composite (Multi-column) Dalawang column o higit pa CREATE INDEX idx_name ON table(col1, col2);
UNIQUE index Index + unique constraint CREATE UNIQUE INDEX idx_name ON table(col);
FULLTEXT index Full-text search CREATE FULLTEXT INDEX idx_name ON table(col);
Index Trade-offs Ang index ay nagpapabilis ng SELECT queries, pero pinapabagal nito ang INSERT, UPDATE, at DELETE dahil kailangan i-update ang index tuwing may pagbabago. Huwag mag-index ng lahat ng columns — piliin lang ang madalas gamitin sa WHERE, JOIN, at ORDER BY.

Kailan Gumamit ng Index?

  • Columns na madalas gamitin sa WHERE clause
  • Columns na ginagamit sa JOIN conditions (foreign keys)
  • Columns na ginagamit sa ORDER BY
  • Columns na may UNIQUE constraint (automatic may index)
  • Huwag mag-index ng columns na bihira gamitin o may kakaunting unique values (e.g., boolean, gender)

Query Optimization gamit ang EXPLAIN

Ang EXPLAIN ay nagpapakita kung paano ini-execute ni MySQL ang iyong query. Ito ang susi sa pag-optimize.

-- Tingnan kung paano ginagawa ang query
EXPLAIN SELECT * FROM users WHERE email = 'juan@example.com';

-- Result:
-- | id | select_type | table | type | possible_keys | key  | rows | Extra       |
-- |----|-------------|-------|------|---------------|------|------|-------------|
-- |  1 | SIMPLE      | users | ref  | idx_email     | idx  |    1 | Using where |

Pag-Interpret ng EXPLAIN Output

Column Meaning Magandang Value
type Paano naghahanap ng rows const, ref, range (masama: ALL = full table scan)
key Anong index ang ginamit May pangalan ng index (NULL ay walang index na ginamit)
rows Tinantyang bilang ng rows na sinuri Mababang numero
Extra Karagdagang impormasyon Using index (maganda); Using filesort (pwedeng i-optimize) 
-- Pag-optimize ng query na may slow EXPLAIN result
-- Kung ang EXPLAIN ay nagpapakita ng type: ALL (full table scan),
-- ibig sabihin walang index na ginagamit.

-- Mag-add ng index sa column na ginagamit sa WHERE
CREATE INDEX idx_orders_customer ON orders(customer_id);
CREATE INDEX idx_orders_date ON orders(order_date);

-- Pagkatapos, i-check ulit
EXPLAIN SELECT * FROM orders
WHERE customer_id = 5
ORDER BY order_date DESC;

Mini-Project: Optimize a Slow Query

Gamit ang isang query na may JOIN at ORDER BY, i-optimize ito gamit ang EXPLAIN at AI:

  1. Gumawa ng dalawang tables: customers (id, name, email) at orders (id, customer_id, total, order_date).
  2. Mag-insert ng sample data.
  3. Patakbuhin ang query na ito: EXPLAIN SELECT c.name, o.total FROM customers c JOIN orders o ON c.id = o.customer_id WHERE o.total > 500 ORDER BY o.order_date DESC;
  4. I-ask si AI: "Based on this EXPLAIN output, what indexes should I add to optimize this query?"
  5. I-add ang suggested indexes at patakbuhin ulit ang EXPLAIN — dapat may improvement.

Summary

  • Constraints (PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK) ay nag-eenforce ng data integrity.
  • Ang index (B-Tree) ay nagpapabilis ng paghahanap — parang table of contents ng libro.
  • Gamitin ang CREATE INDEX sa columns na madalas gamitin sa WHERE, JOIN, at ORDER BY.
  • Ang EXPLAIN ay nagpapakita kung paano ini-execute ang query — i-check ang type, key, at rows.
  • I-prompt si AI para mag-suggest ng indexes base sa iyong queries at EXPLAIN output.
