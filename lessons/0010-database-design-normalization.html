Lesson 0010: Database Design & Normalization

Matutong mag-design ng maayos na database schema at i-apply ang normalization para maiwasan ang data redundancy.

Lesson Goal Makapag-design ng normalized database schema para sa totoong applications, makagamit ng AI para mag-suggest ng table structures, at maintindihan ang 1NF, 2NF, at 3NF.

Entity-Relationship Diagrams (ERD)

Ang ERD ay parang blueprint ng iyong database. Ipinapakita nito ang entities (tables), attributes (columns), at relationships (foreign keys) sa visual na paraan.

Pag-generate ng ERD gamit ang AI

Sa halip na gumuhit manually, i-prompt mo lang si AI:

"I-design mo ang database schema para sa isang e-commerce app na may users, products, orders, at reviews."

Ang AI ay magbi-generate ng schema na may:

  • Users — id, name, email, password, address, created_at
  • Products — id, name, description, price, stock, category_id
  • Orders — id, user_id (FK), order_date, status, total
  • Order_Items — id, order_id (FK), product_id (FK), quantity, price
  • Reviews — id, product_id (FK), user_id (FK), rating, comment, created_at
  • Categories — id, name, slug
AI Prompt Template "Design a MySQL database schema for a [app type]. Include tables for [list of entities]. Define primary keys, foreign keys, and relationships."

Database Normalization

Ang normalization ay proseso ng pag-oorganisa ng data para mabawasan ang redundancy at maiwasan ang anomalies (insertion, update, deletion anomalies).

First Normal Form (1NF)

Mga requirements:

  • Bawat column ay dapat atomic (isang value lang per cell)
  • Bawat row ay dapat unique (may primary key)
-- Violation ng 1NF: multiple values sa isang column
CREATE TABLE student_courses (
    student_id INT,
    student_name VARCHAR(100),
    courses VARCHAR(255) -- 'Math,Science,English' — violation!
);

-- 1NF Compliant: isang course per row
CREATE TABLE student_courses (
    id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT,
    course_name VARCHAR(100)
);

Second Normal Form (2NF)

Requirements:

  • Dapat nasa 1NF na
  • Lahat ng non-key columns ay dapat fully functionally dependent sa buong primary key (walang partial dependency)
-- Violation ng 2NF: partial dependency
-- Kung ang primary key ay (order_id, product_id):
CREATE TABLE order_details (
    order_id INT,
    product_id INT,
    product_name VARCHAR(200), -- Depende lang sa product_id, hindi sa buong PK
    quantity INT,
    PRIMARY KEY (order_id, product_id)
);

-- 2NF Compliant: hiwalay ang products table
CREATE TABLE products (
    id INT PRIMARY KEY,
    name VARCHAR(200)
);

CREATE TABLE order_items (
    order_id INT,
    product_id INT,
    quantity INT,
    PRIMARY KEY (order_id, product_id),
    FOREIGN KEY (product_id) REFERENCES products(id)
);

Third Normal Form (3NF)

Requirements:

  • Dapat nasa 2NF na
  • Walang transitive dependency — ang non-key columns ay hindi dapat dependent sa ibang non-key columns
-- Violation ng 3NF: transitive dependency
CREATE TABLE orders (
    id INT PRIMARY KEY,
    customer_id INT,
    customer_name VARCHAR(100), -- Depende sa customer_id (non-key), hindi sa id (PK)
    customer_email VARCHAR(100), -- Depende sa customer_id (non-key)
    order_date DATETIME,
    total DECIMAL(10,2)
);

-- 3NF Compliant: hiwalay ang customers table
CREATE TABLE customers (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100)
);

CREATE TABLE orders (
    id INT PRIMARY KEY,
    customer_id INT,
    order_date DATETIME,
    total DECIMAL(10,2),
    FOREIGN KEY (customer_id) REFERENCES customers(id)
);

Pag-design ng Schema para sa Iba't Ibang Apps

Blog Platform

-- Users, Posts, Comments, Categories
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100) UNIQUE,
    bio TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE categories (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    slug VARCHAR(100) UNIQUE
);

CREATE TABLE posts (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    category_id INT,
    title VARCHAR(255),
    slug VARCHAR(255) UNIQUE,
    content TEXT,
    published_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (category_id) REFERENCES categories(id)
);

CREATE TABLE comments (
    id INT AUTO_INCREMENT PRIMARY KEY,
    post_id INT NOT NULL,
    user_id INT NOT NULL,
    body TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (post_id) REFERENCES posts(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);

Task Management App

-- Users, Projects, Tasks, Labels
CREATE TABLE projects (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(200),
    description TEXT,
    user_id INT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE TABLE tasks (
    id INT AUTO_INCREMENT PRIMARY KEY,
    project_id INT,
    title VARCHAR(255),
    description TEXT,
    status ENUM('todo', 'in_progress', 'done') DEFAULT 'todo',
    priority ENUM('low', 'medium', 'high') DEFAULT 'medium',
    due_date DATE,
    assigned_to INT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES projects(id),
    FOREIGN KEY (assigned_to) REFERENCES users(id)
);

Paggamit ng AI sa Schema Design

I-prompt si AI para mag-suggest ng optimal table structures:

Effective AI Prompts para sa Database Design
  • "Design a normalized MySQL schema for a blog with users, posts, comments, categories, and tags. Include foreign keys and indexes."
  • "I have a denormalized table with [describe structure]. Help me normalize it to 3NF."
  • "Generate an ERD description for a task management app with projects, tasks, and assignees."
  • "What's the best way to model a many-to-many relationship between posts and tags?"

"Sabihin mo kay AI: 'I-design mo ang database schema para sa isang [app type] na may [entities].' — at kusa na itong magge-generate ng CREATE TABLE statements, foreign keys, at indexes."

Quick Quiz

2. Aling normal form ang nagre-require na ang bawat column ay atomic (isang value lang per cell)?
3. Ano ang tawag kapag ang isang non-key column ay dependent sa ibang non-key column (hindi sa primary key)?

Mini-Project: Blog Platform Schema Design

Mag-design ng normalized database schema para sa isang blog platform. Dapat may mga sumusunod na entities:

  • Users — name, email, avatar, bio
  • Posts — title, slug, content, published date, status
  • Comments — body, created date, status (approved/pending)
  • Categories — name, slug, description

Steps:

  1. I-ask si AI: "Design a normalized MySQL database schema for a blog platform with users, posts, comments, and categories. Include foreign keys and ensure 3NF."
  2. I-review ang AI-generated schema at i-check kung nasunod ang normalization rules.
  3. Gawin ang CREATE TABLE statements at patakbuhin sa MySQL.
  4. Mag-insert ng sample data at i-test ang relationships.

Summary

  • Ang ERD ay visual representation ng database structure — pwedeng i-generate gamit ang AI.
  • 1NF: Atomic columns at may primary key.
  • 2NF: Walang partial dependency (depende sa part lang ng composite key).
  • 3NF: Walang transitive dependency (non-key column na dependent sa ibang non-key column).
  • Gamitin ang AI para mag-design at mag-review ng schema — prompt ito ng "Design a normalized schema for..."
