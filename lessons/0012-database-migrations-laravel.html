Lesson 0012: Database Migrations with Laravel

Matutong gumamit ng Laravel migrations para ma-version control ang iyong database schema.

Lesson Goal Ma-explain kung ano ang migrations, makagawa ng migration files gamit ang artisan, mag-apply at mag-rollback ng migrations, at magamit ang AI para mag-generate ng migration files.

Ano ang Database Migrations?

Sa Laravel, hindi ka direktang gumagawa ng table sa phpMyAdmin — migration files ang gamit para version-controlled ang schema.

Ang migrations ay parang Git para sa database schema. Sa halip na manual na gumawa ng tables sa phpMyAdmin, nagsusulat ka ng PHP code na nagdi-describe ng schema, at ito ay naka-commit kasama ng iyong codebase.

Bakit Migrations?

  • Version control — nasa Git ang schema changes, kasama ng application code
  • Reproducible — kahit sino sa team, isang php artisan migrate lang, updated na ang database
  • Rollback — pwedeng i-undo ang changes kung may mali
  • Deployment — automated ang schema updates sa production

"Sa Laravel, hindi ka direktang gumagawa ng table sa phpMyAdmin — migration files ang gamit para version-controlled ang schema. Isipin mo itong parang 'git para sa database.'"

Pag-gawa ng Migration Files

1

Gumawa ng migration

php artisan make:migration create_products_table

Mage-generate ito ng file sa database/migrations/ na may timestamp at pangalan.

2

I-edit ang migration file

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('products', function (Blueprint $table) {
            $table->id();
            $table->string('name', 200);
            $table->text('description')->nullable();
            $table->decimal('price', 10, 2);
            $table->integer('stock')->default(0);
            $table->boolean('is_available')->default(true);
            $table->string('category')->nullable();
            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('products');
    }
};
3

Run the migration

php artisan migrate

Ito ang mag-e-execute ng up() method at gagawin ang products table.

Running at Rolling Back Migrations

# I-run lahat ng pending migrations
php artisan migrate

# I-rollback ang last batch
php artisan migrate:rollback

# I-rollback ang specific number of steps
php artisan migrate:rollback --step=3

# I-rollback lahat at i-migrate ulit
php artisan migrate:refresh

# I-drop lahat ng tables at i-migrate ulit
php artisan migrate:fresh

# Tingnan ang status ng migrations
php artisan migrate:status
migrate:fresh vs migrate:refresh migrate:fresh — drop lahat ng tables at i-run lahat ng migrations. migrate:refresh — i-rollback lahat at i-migrate ulit. Sa development, mas gamitin ang migrate:fresh dahil mas mabilis.

Summary

  • Ang migrations ay version control para sa database schema — nasa Git ang lahat ng changes.
  • Gumamit ng php artisan make:migration para gumawa ng migration file.
  • ILagay ang schema changes sa up() method at ang reverse sa down() method.
  • Gamitin ang Schema Builder methods: id(), string(), text(), decimal(), foreignId(), atbp.
  • I-prompt si AI para mag-generate ng migration code.
