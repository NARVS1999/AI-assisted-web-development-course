Lesson 0034: Fetching Data from Laravel API to Next.js

Paano kumuha ng data mula sa Laravel API papunta sa Next.js frontend gamit ang server-side fetching at API service files.

Lesson Goal Makagawa ng API service file sa Next.js na kumukuha ng data mula sa Laravel backend, na may proper loading, error, at success states.

Server-Side Fetching vs Client-Side Fetching

Sa Next.js App Router, puwedeng mag-fetch ng data sa Server Components (direkta, walang useEffect) o sa Client Components (gamit ang useEffect o libraries).

// Server Component — mag-fetch sa server
export default async function ProductsPage() {
  const res = await fetch('http://localhost:8000/api/v1/products', {
    cache: 'no-store' // para laging fresh data
  });
  const products = await res.json();
  return <ProductList products={products} />;
}
Tip Sa Server Components, hindi kailangan ng loading/error states dahil ang error ay mapupunta sa error.js at loading sa loading.js.

Axios vs Native Fetch

FeatureNative FetchAxios
Built-in✓ Yes✗ Need install
Interceptors✗ Manual✓
Automatic JSON✗ Need .json()✓ Auto
Error Handling✗ Only network errors✓ HTTP errors included
Request Cancel✗ AbortController✓ CancelToken

Para sa course na ito, gagamit tayo ng Axios dahil mas madali ang error handling at may interceptors.

Creating an API Service File

Gumawa ng api.ts file na naglalaman ng lahat ng API calls — para isang lugar lang ang titingnan.

// lib/api.ts
import axios from 'axios';

const api = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8000/api/v1',
  headers: { 'Content-Type': 'application/json' },
  withCredentials: true,
});

// Response interceptor
api.interceptors.response.use(
  response => response,
  error => {
    console.error('API Error:', error.response?.data || error.message);
    return Promise.reject(error);
  }
);

export default api;

Handling Loading, Error, at Success States

Sa Client Components, gamitin ang useState at useEffect para sa tatlong states:

'use client';
import { useState, useEffect } from 'react';
import api from '@/lib/api';

export default function ProductList() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    api.get('/products')
      .then(res => setProducts(res.data.data))
      .catch(err => setError(err.message))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;
  return <!-- render products -->;
}

Using AI para gumawa ng API Service

I-prompt si AI para gumawa ng kumpletong API service file:

"Gumawa ng Axios API service file for Next.js na may baseURL na naka-configure para sa Laravel backend. Dapat may getAllProducts, getProduct, createProduct, updateProduct, at deleteProduct functions. May proper error handling at TypeScript types."
Key Insight Ang API service file ay nagse-centralize ng lahat ng network calls — mas madaling i-maintain at i-debug kaysa scattered fetch calls sa buong app.

Mini-Project: Gumawa ng API Service File gamit ang AI

Gamit ang AI, gumawa ng API service file na may mga sumusunod:

  1. Mag-create ng lib/api.ts na may Axios instance
  2. I-prompt si AI: "Generate an API service file for Next.js with functions: getAllProducts, getProduct(id), createProduct(data), updateProduct(id, data), deleteProduct(id). Use Axios with proper TypeScript types."
  3. Magdagdag ng response at request interceptors
  4. I-import at gamitin ang service sa isang page component

Summary

  • Gumamit ng Server Components para sa direktang data fetching
  • Axios ay mas maganda para sa error handling at interceptors kumpara sa native fetch
  • Palaging mag-handle ng loading, error, at success states
  • I-centralize ang API calls sa isang service file para sa mas madaling maintenance
