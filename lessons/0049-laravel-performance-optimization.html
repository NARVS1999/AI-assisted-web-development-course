Lesson 0049: Laravel Performance Optimization

Gamitin ang Laravel Debugbar para makita ang queries — kapag maraming duplicate, may problema.

Lesson Goal Matutunan ang query optimization, caching strategies, queue optimization, at kung paano gamitin si AI para mag-identify ng performance bottlenecks.

Query Optimization: N+1 Problem at Eager Loading

Ang N+1 problem ay isa sa pinakakaraniwang performance issue sa Laravel. Nangyayari ito kapag nag-lo-loop ka ng models at nag-a-access ng relationship sa bawat iteration:

// N+1 Problem — gumagawa ng 1 query para sa products + N queries para sa categories
$products = Product::all();
foreach ($products as $product) {
    echo $product->category->name; // N+1 queries!
}

// Solution: Eager Loading — 2 queries lang total
$products = Product::with('category')->get();

I-install ang Laravel Debugbar para makita ang mga queries:

composer require barryvdh/laravel-debugbar --dev
Tip Kapag nakita mong maraming duplicate queries sa Debugbar, eager loading ang sagot. I-prompt si AI: "I have an N+1 problem with my Product and Category relationship. Show me how to fix it using eager loading."

Caching Strategies (Redis, Model Caching)

Ang caching ay pag-store ng data para hindi na kailangang i-query ulit. Gamitin ang Redis o database cache:

// Cache ng products for 60 minutes
$products = Cache::remember('products.all', 3600, function () {
    return Product::with('category')->get();
});

// Model caching gamit ang Laravel Model Caching package
// Automatic na na-invalidate ang cache kapag nag-update ng model
$products = Product::with('category')->cacheFor(3600)->get();
Key Insight Hindi lahat ng data kailangang i-cache. I-cache lang ang data na: 1) madalas i-access, 2) hindi madalas magbago, at 3) mahal i-compute (e.g., complex queries).

Queue Optimization

Ilipat ang mababagal na tasks (email sending, image processing, report generation) sa queues para hindi ma-block ang HTTP response:

// Instead of doing this synchronously
Mail::to($user)->send(new OrderConfirmation($order));

// Dispatch to queue
ProcessOrder::dispatch($order)->onQueue('high');

I-configure ang queue connection sa .env:

QUEUE_CONNECTION=database

I-run ang queue worker:

php artisan queue:work

Using AI to Identify Performance Bottlenecks

I-paste ang query log o Debugbar output kay AI at humingi ng optimization suggestions:

"Here are my Laravel Debugbar queries for the products page. I have 100 duplicate category queries. How do I fix this? Here's my controller code: ..."

Puwede ring mag-prompt ng AI para mag-analyze ng slow queries:

"I have a Laravel page that takes 5 seconds to load. Here's the controller code and the queries from Debugbar. What's the bottleneck and how do I optimize it?"

Mini-Project: AI Analyzes a Slow Query

Gumawa ng isang intentional N+1 problem sa iyong Laravel app, i-present kay AI, at mag-suggest ng fix:

  1. Gumawa ng Controller method na naglo-load ng lahat ng products at nag-a-access ng category relationship sa loob ng loop (walang eager loading)
  2. I-install ang Laravel Debugbar at i-load ang page — tingnan ang dami ng queries
  3. I-copy ang controller code at query info
  4. I-prompt kay AI: "This controller loads products and their categories, but I see N+1 queries in Debugbar. Here's my code. How do I fix this with eager loading?"
  5. I-apply ang fix na sinuggest ni AI at i-verify na bumaba ang bilang ng queries

Summary

  • Ang N+1 problem ay common performance issue — solusyon ay eager loading gamit ang with()
  • Gamitin ang Laravel Debugbar para makita ang mga queries na tumatakbo
  • I-cache ang data na madalas i-access, hindi madalas magbago, at mahal i-compute
  • Ilipat ang heavy tasks sa queues para hindi ma-block ang HTTP response
  • Si AI ay magaling mag-analyze ng bottleneck — i-paste ang Debugbar output at code
