Lesson 0055: MySQL Database in Production

Alamin ang best practices para sa MySQL database sa production — managed databases, backups, at zero-downtime migrations.

Lesson Goal Maunawaan ang managed database options, makapag-setup ng automated backups, at makapag-plano ng database migration strategy na walang downtime.

Managed Database Options

Sa production, hindi advisable na i-run ang MySQL sa same server ng iyong application. Mas maganda ang managed databases — sila na ang bahala sa maintenance, backups, at scaling.

Service Free Tier Pros Best for
PlanetScale 1 GB storage, 1 billion row reads/month Serverless, branching workflow, automatic backups Modern apps na gusto ng developer-friendly DB
DigitalOcean Managed DB Wala Full MySQL access, daily backups, point-in-time recovery Apps na naka-host sa DigitalOcean
AWS RDS Wala (may 12-month free tier) Highly scalable, multi-AZ, automated patching Enterprise at high-traffic apps
Railway $5 credit monthly Simple setup, built-in backups Startups at small teams
Tip Kung naghahanap ka ng libre para sa small project, maganda ang PlanetScale. May branching workflow na parang Git para sa database — pwedeng mag-branch, mag-migrate, at mag-deploy.

Backups at Disaster Recovery

"Huwag kalimutang mag-backup ng database — automated gabi-gabi. Kapag nasira, may babalikan."

May dalawang uri ng backup:

  • Logical Backup — Gamit ang mysqldump. Gumagawa ng SQL file ng lahat ng data at schema. Mabagal para sa malaking database pero portable.
  • Physical Backup — Kopya ng actual database files. Mas mabilis, ideal para sa malalaking databases.
# Basic mysqldump backup
mysqldump -u root -p --all-databases > full_backup.sql

# I-compress para makatipid ng space
mysqldump -u root -p myapp_db | gzip > myapp_db_$(date +%F).sql.gz

# Restore mula sa backup
mysql -u root -p myapp_db < backup.sql
gunzip -c myapp_db_2026-07-06.sql.gz | mysql -u root -p myapp_db

Database Migration sa Production — Zero Downtime

Ang php artisan migrate ay pwedeng mag-lock ng tables. Para iwasan ang downtime:

1

I-deploy muna ang code na backward compatible: Ang bagong code ay dapat gumana sa lumang schema.

2

I-run ang migration: Gamitin ang php artisan migrate --force. Kung may ALTER TABLE na magla-lock, gamitin ang pt-online-schema-change.

3

I-deploy ang bagong code na dependent sa bagong schema: Pagkatapos ng successful migration, i-deploy ang code na gumagamit ng bagong columns/tables.

# Gamit ang Laravel — dapat naka-maintenance mode deviation
# I-check muna kung may mga pending migration
php artisan migrate:status

# I-run nang may --pretend para i-preview
php artisan migrate --pretend --force

# Actual migration
php artisan migrate --force

# Rollback kung may problema
php artisan migrate:rollback --step=1 --force

Using AI para ma-Generate ang Backup Scripts

I-prompt si AI para gumawa ng automated backup script:

Prompt para kay AI:
"Gumawa ka ng bash script para sa automated MySQL backup.
Isama ang:
- Daily backup gamit ang mysqldump
- I-compress ang backup gamit ang gzip
- I-delete ang backups na mas luma sa 30 days
- I-send ang backup sa remote server o S3
- I-log ang success o failure
- I-set bilang cron job"

Prompt para kay AI:
"Generate a cron job configuration na nagra-run ng MySQL backup every day at 2 AM at nagre-retain ng 7 days of backups."

Gamit ang AI, i-generate ang isang automated MySQL backup script. I-prompt si AI:

"Generate a bash script that performs daily MySQL backups using mysqldump, compresses them with gzip, deletes backups older than 7 days, and logs the results to a file."

I-save ang script bilang backup.sh. I-edit at i-customize para sa iyong database configuration. I-set up ang cron job para mag-run araw-araw.

Summary

  • Gamitin ang managed databases (PlanetScale, DigitalOcean, AWS RDS) para sa production.
  • Mag-setup ng automated daily backups gamit ang mysqldump at cron.
  • I-compress ang backups para makatipid ng storage space.
  • Para sa zero-downtime migration, i-deploy muna ang backward-compatible code.
  • Gamitin ang AI para mag-generate ng backup scripts at cron configurations.
