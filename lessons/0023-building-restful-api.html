RESTful API Conventions

Ang REST (Representational State Transfer) ay isang architectural style para sa APIs. Ang resources ay nire-represent bilang URLs at ginagamit ang HTTP methods para sa CRUD operations.

HTTP MethodEndpointAction
GET/api/tasksList all tasks
POST/api/tasksCreate a new task
GET/api/tasks/{id}Show a single task
PUT/PATCH/api/tasks/{id}Update a task
DELETE/api/tasks/{id}Delete a task

Nested Resources

Para sa related resources, gumamit ng nesting:

GET /api/users/{user}/tasks     // Tasks ng isang user
POST /api/users/{user}/tasks    // Gumawa ng task para sa user

API Versioning

Para hindi ma-break ang existing clients kapag may changes, mag-version ng API:

// routes/api.php
Route::prefix('v1')->group(function () {
    Route::apiResource('tasks', TaskController::class);
});

Route::prefix('v2')->group(function () {
    Route::apiResource('tasks', V2\TaskController::class);
});

Building a Complete CRUD API

Sa lesson na ito, gagamitin natin si AI para i-scaffold ang buong API para sa isang Task model.

1

Create Model with Migration

php artisan make:model Task -m

I-prompt si AI: "Generate the migration for a tasks table with title, description, status, due_date, and user_id fields."

2

Create Controller with API Resource

php artisan make:controller TaskController --api
php artisan make:resource TaskResource

I-prompt si AI: "Generate a TaskController with full CRUD methods and a TaskResource."

3

Define Routes

Route::apiResource('tasks', TaskController::class);
4

Add Form Request Validation

I-prompt si AI: "Generate a StoreTaskRequest with validation rules for title (required), description (nullable), status (in: pending,in_progress,done), and due_date (nullable, date)."

5

Test with Postman or curl

curl -X GET http://localhost:8000/api/tasks
curl -X POST http://localhost:8000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "My Task", "status": "pending"}'

Summary

  • Ang RESTful API ay gumagamit ng HTTP methods (GET, POST, PUT/PATCH, DELETE)
  • Ang nested resources ay para sa related data (e.g., /users/{id}/tasks)
  • Gamitin ang route prefixes para sa API versioning (v1, v2)
  • Ang Route::apiResource() ay automatic na gumagawa ng CRUD routes
  • Gamitin si AI para i-scaffold ang buong API sa isang prompt lang
