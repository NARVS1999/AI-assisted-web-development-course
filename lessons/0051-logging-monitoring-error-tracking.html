Lesson 0051: Logging, Monitoring & Error Tracking

Kapag nasa production na, hindi mo na pwedeng i-dd() ang errors — kailangan ng proper logging at monitoring.

Lesson Goal Matutunan ang Laravel logging, frontend error tracking gamit ang Sentry, health checks, at paggamit ng AI para mag-set up ng monitoring.

Laravel Logging (Daily Logs, External Services)

Ang Laravel ay may built-in na logging system gamit ang Log facade. I-configure sa config/logging.php:

// logging.php — daily logs
'channels' => [
    'stack' => [
        'driver' => 'stack',
        'channels' => ['daily', 'sentry'],
    ],
    'daily' => [
        'driver' => 'daily',
        'path' => storage_path('logs/laravel.log'),
        'days' => 14, // keep logs for 14 days
    ],
],

Gamitin sa code:

// Instead of dd() or dump()
Log::info('User registered', ['user_id' => $user->id]);
Log::error('Payment failed', [
    'order_id' => $order->id,
    'error' => $e->getMessage()
]);
Best Practice Mag-log laging may context: huwag lang "Error occurred" kundi "Payment failed for order #1234: insufficient funds".

Frontend Error Tracking (Sentry)

Ang Sentry ay isang error tracking service para sa frontend at backend. I-set up sa Next.js:

npm install @sentry/nextjs
npx @sentry/wizard -i nextjs

Awtomatikong magca-capture ng errors ang Sentry at magse-send ng alert sa iyo:

// Manual error reporting
import * as Sentry from '@sentry/nextjs';

try {
  // some code
} catch (error) {
  Sentry.captureException(error);
}

// Sa API routes
export default function handler(req, res) {
  try {
    // ...
  } catch (error) {
    Sentry.captureException(error);
    return res.status(500).json({ error: 'Internal Server Error' });
  }
}
Key Insight Sentry ay libre para sa small teams at personal projects. I-set up na bago mag-deploy sa production — hindi mo na kailangan manghingi ng screenshot sa users para malaman ang error.

Health Checks at Monitoring

Gumawa ng health check endpoint para ma-monitor ang status ng iyong app:

// routes/api.php
Route::get('/health', function () {
    try {
        DB::connection()->getPdo();
        return response()->json([
            'status' => 'healthy',
            'database' => 'connected',
            'timestamp' => now()
        ]);
    } catch (\Exception $e) {
        return response()->json([
            'status' => 'unhealthy',
            'error' => $e->getMessage()
        ], 500);
    }
});

Para sa monitoring, gumamit ng uptime monitors tulad ng UptimeRobot (libre) o Better Uptime na nagche-check ng health endpoint every 5 minutes.

Using AI to Set Up Monitoring

I-prompt si AI para mag-set up ng monitoring infrastructure:

"I need to set up Sentry for my Next.js app and create a health check endpoint in Laravel. How do I configure both? Give me step-by-step instructions."

Puwede ring humingi ng troubleshooting help:

"My Sentry is not capturing errors from my Next.js API routes. Here's my sentry.config.js. What's wrong?"
Warning Huwag mag-log ng sensitive data: passwords, credit card numbers, personal information. I-configure ang data scrubbing sa Sentry para i-automate ito.

Mini-Project: Sentry Setup at Health Check Endpoint

Gamit ang AI, mag-set up ng error tracking at health monitoring:

  1. I-set up ang Sentry sa iyong Next.js project. Mag-sign up sa sentry.io, pagkatapos ay i-prompt si AI: "Guide me through setting up @sentry/nextjs in my Next.js project step by step."
  2. Gumawa ng health check endpoint sa Laravel na nagche-check ng database connection at nagbabalik ng JSON response
  3. I-configure ang Laravel logging na mag-log sa daily files at (optional) sa Sentry
  4. I-test na may na-ca-capture na errors ang Sentry — gumawa ng intentional error sa frontend at backend

Ang goal ay magkaroon ka ng visibility sa production errors nang hindi mo na kailangan hulaan kung ano ang problema.

Summary

  • Gamitin ang Log::info() at Log::error() sa Laravel — hindi dd() sa production
  • Sentry para sa frontend at backend error tracking — automatic error alerts
  • Health check endpoint para sa uptime monitoring (e.g., UptimeRobot)
  • Huwag mag-log ng sensitive data — i-configure ang data scrubbing
  • Si AI ay magaling mag-guide sa pag-set up ng monitoring infrastructure
