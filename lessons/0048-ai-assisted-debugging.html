Lesson 0048: AI-Assisted Debugging Techniques

I-paste mo lang ang error message kay AI: "Bakit nagkakaganito ang error na 'to? Paano i-fix?"

Lesson Goal Matutunan kung paano gamitin si AI para mag-analyze ng error messages, stack traces, at mag-suggest ng fixes.

Using AI to Explain Error Messages

Sa halip na i-Google ang error message, i-paste mo na lang kay AI. Halimbawa:

"I'm getting this error in Laravel: 'Target class [ProductController] does not exist.' What does it mean and how do I fix it?"

Sasagot si AI ng:

  • Explanation kung bakit nangyayari ang error (missing import, typo sa route, hindi na-register ang controller)
  • Step-by-step fix (import ang controller, check ang route definition, o i-register sa service provider)

Tip Magbigay ng context sa AI: anong framework, anong file, anong line. Kung mas maraming context, mas accurate ang diagnosis.

"Rubber Duck Debugging" with AI

Ang rubber duck debugging ay ang pag-explain ng code sa isang rubber duck (o kahit kanino) para makita ang problema. Ngayon, si AI na ang rubber duck mo:

"I'm trying to fetch products from my Laravel API in Next.js. Here's my code. Hindi nagwo-work ang fetch — laging network error. Ano kaya ang problema?"

Sa pag-explain mo ng problema kay AI, madalas ay mare-realize mo na ang solution habang nagta-type ka pa lang — at kung hindi, si AI na ang bahala.

Stack Trace Analysis at AI-Suggested Fixes

Kapag may exception ka, i-paste ang buong stack trace kay AI kasama ang context:

// I-paste kay AI ang stack trace
SQLSTATE[23000]: Integrity constraint violation: 1048 Column 'email' cannot be null
  at ...
  at ...
  in file app/Http/Controllers/UserController.php:45

I-prompt si AI:

"This is the stack trace from my Laravel app. The error is an integrity constraint violation on the email column. Here's the code at line 45. What's causing this and how should I fix it?"
Key Insight Huwag mag-panic sa error messages. I-copy ang error, i-paste kay AI, at intindihin ang explanation. Ang errors ay opportunities para matuto.

AI Debugging Best Practices

  • Provide full context: Framework version, file name, line number, surrounding code
  • Include the actual error: I-copy ang exact error message at stack trace
  • Tell AI what you tried: "I already checked the database and the column exists..."
  • Ask specific questions: "Is the problem in my validation or in the database schema?"
  • Don't blindly apply fixes: Intindihin ang suggestion ni AI bago i-implement
Warning Huwag mag-paste ng sensitive information (passwords, API keys, database credentials) kay AI. I-mask o i-redact muna.

Mini-Project: Debug an Actual Error with AI

Maghanap ng actual error mula sa iyong project (o gumawa ng intentional error), i-paste kay AI, at i-apply ang fix:

  1. Gumawa ng intentional error sa iyong Laravel o Next.js project (halimbawa: mag-access ng undefined variable o mag-call ng non-existent method)
  2. I-copy ang error message at stack trace
  3. I-paste kay AI kasama ang prompt: "I'm getting this error in [framework]. Here's the stack trace and the relevant code. What's causing it and how do I fix it?"
  4. I-analyze ang response ni AI at i-apply ang suggested fix
  5. I-document kung ano ang error, ano ang sinabi ni AI, at kung paano mo ito na-fix

Ang goal ay hindi lang ma-fix ang error — kundi maintindihan kung bakit ito nangyari.

Summary

  • I-paste ang error messages + stack traces + code context kay AI para sa mabilis na diagnosis
  • Rubber duck debugging with AI = i-explain ang problema, si AI ang tutulong mag-solve
  • Magbigay ng context: framework version, file, line number, at kung ano na ang sinubukan mo
  • Huwag blindly apply fixes — intindihin muna ang suggestion ni AI
  • Wag mag-paste ng sensitive information (passwords, API keys, tokens)
