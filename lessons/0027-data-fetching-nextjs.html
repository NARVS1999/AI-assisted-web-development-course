Lesson 0027: Data Fetching sa Next.js

Matutong mag-fetch ng data sa Next.js gamit ang Server Components at Client Components, at maintindihan ang Static vs Dynamic rendering.

Lesson Goal Makapag-fetch ng data mula sa API gamit ang server-side at client-side approaches, at malaman kung kailan gagamitin ang Static vs Dynamic rendering.

Server-Side Data Fetching (Server Components)

Sa Next.js App Router, ang Server Components ay puwedeng mag-fetch ng data nang direkta sa server — walang need na useEffect, walang loading spinners, at secure dahil hindi exposed ang API keys sa browser.

// app/products/page.tsx — Server Component (default)
async function getProducts() {
  const res = await fetch('https://api.example.com/products');
  if (!res.ok) throw new Error('Failed to fetch');
  return res.json();
}

export default async function ProductsPage() {
  const products = await getProducts();

  return (
    <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
      {products.map((product: any) => (
        <div key={product.id} className="border rounded p-4">
          <h2>{product.name}</h2>
          <p>₱{product.price}</p>
        </div>
      ))}
    </div>
  );
}
"Sa Next.js, puwedeng sa server pa lang naka-fetch na ang data (server components) o sa browser (client components)."
Tip Ang fetch sa Server Components ay may built-in na caching at revalidation. Default ay force-cache — i-set ang cache: 'no-store' para laging fresh ang data.

Client-Side Data Fetching

Para sa interactive pages na nangangailangan ng real-time data o user-triggered requests, gamitin ang client-side fetching:

Gamit ang useEffect + fetch

'use client';
import { useState, useEffect } from 'react';

export default function ClientProducts() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('/api/products')
      .then(res => {
        if (!res.ok) throw new Error('Failed');
        return res.json();
      })
      .then(data => { setProducts(data); setLoading(false); })
      .catch(err => { setError(err.message); setLoading(false); });
  }, []);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <div>
      {products.map(p => <div key={p.id}>{p.name}</div>)}
    </div>
  );
}

Gamit ang SWR o React Query

Para sa mas advanced na data fetching, gamitin ang SWR (by Vercel) o TanStack React Query — may built-in caching, revalidation, at pagination:

'use client';
import useSWR from 'swr';

const fetcher = (url: string) => fetch(url).then(res => res.json());

export default function Products() {
  const { data, error, isLoading } = useSWR('/api/products', fetcher);

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>Error loading products</p>;

  return data.map((p: any) => <div key={p.id}>{p.name}</div>);
}

Static vs Dynamic Rendering

Ang Next.js ay may dalawang rendering strategies:

Strategy Kailan ginagamit Paano i-enable
Static (SSG) Content na hindi madalas magbago (blog posts, docs) Default sa Server Components with fetch at cache: 'force-cache'
Dynamic (SSR) User-specific o real-time data cache: 'no-store' o export const dynamic = 'force-dynamic'
ISR Content na nagbabago periodically next: { revalidate: 3600 } — revalidate every hour 
// Static (default) — fetched at build time
const data = await fetch('https://api.example.com/posts');

// Dynamic — fetched every request
const data = await fetch('https://api.example.com/posts', { cache: 'no-store' });

// ISR — revalidates every 60 seconds
const data = await fetch('https://api.example.com/posts', { next: { revalidate: 60 } });

Using AI para Mag-generate ng Data Fetching Logic

Ang AI ay mahusay sa pag-generate ng data fetching code. Narito ang magandang prompt pattern:

  • I-specify kung Server Component o Client Component.
  • Ibigay ang API endpoint at response structure.
  • I-request ang loading at error states.
  • I-request ang caching/rendering strategy.

Halimbawa prompt:

"Create a Next.js 14 Server Component page for products that fetches from 'https://api.example.com/products'. Each product has id, name, price, and image. Display them in a responsive grid with Tailwind CSS. Use dynamic rendering (no-store cache)."

Gumawa ng products page na nagfe-fetch mula sa isang external API (simulate a Laravel API):

  • Gumamit ng Server Component na nagfa-fetch ng products list.
  • I-display ang products sa responsive grid (1 col mobile, 3 cols desktop).
  • Maglagay ng loading.tsx file para sa streaming.
  • I-handle ang error case (e.g., API down) gamit ang error.tsx.

Prompt tip: "Create a Next.js 14 page that fetches products from 'https://fakestoreapi.com/products' using a Server Component. Display them in a responsive grid. Also create loading.tsx and error.tsx files. Use TypeScript and Tailwind CSS."

Summary

  • Ang Server Components ay nagfa-fetch ng data sa server — walang loading state, secure, at mas mabilis.
  • Ang Client Components ay gumagamit ng useEffect + fetch o libraries tulad ng SWR/React Query.
  • Static rendering (force-cache) ay para sa content na bihirang magbago; Dynamic (no-store) para sa real-time data.
  • ISR (revalidate) ay combination ng static at dynamic — nagre-revalidate sa background.
  • Gamitin ang AI para mag-generate ng fetching logic — specify mo lang ang API, component type, at rendering strategy.
