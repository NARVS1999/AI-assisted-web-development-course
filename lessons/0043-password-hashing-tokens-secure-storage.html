Lesson 0043: Password Hashing, Tokens & Secure Storage

Huwag i-store ang tokens sa localStorage kung puwede sa httpOnly cookies.

Lesson Goal Maunawaan ang bcrypt hashing sa Laravel, ang pagkakaiba ng JWT at opaque tokens, ang secure storage ng tokens (httpOnly cookies vs localStorage), at ma-implement ang password reset flow gamit ang AI.

Password Hashing gamit ang bcrypt

Ang Laravel ay gumagamit ng bcrypt para i-hash ang passwords. Huwag mag-imbak ng plain text passwords!

// Sa User model — automatic na naka-hash ang password
use Illuminate\Support\Facades\Hash;

// Manual hashing
$hashed = Hash::make('plain-text-password');

// Validation
if (Hash::check('plain-text-password', $hashed)) {
    // Mag-match ang password
}

// Sa User model (automatic)
protected function password(): Attribute
{
    return Attribute::make(
        set: fn (string $value) => Hash::make($value),
    );
}
Tip "Ang bcrypt ay parang meat grinder — madaling mag-hash pero sobrang hirap i-reverse. Kahit makuha ng hacker ang database, hindi niya mababasa ang passwords."

JWT vs Opaque Tokens

Feature JWT Opaque Tokens
Format JSON payload na naka-encode Random string
Self-contained Oo — may data sa loob ng token Hindi — need i-query sa database
Revocation Need blacklist (hindi instant) Instant — delete lang sa database
Use case Stateless APIs, mobile apps Server-side sessions, SPAs

Secure Token Storage

May dalawang paraan mag-store ng tokens sa frontend:

  • httpOnly Cookies — Hindi ma-access ng JavaScript. Protected laban sa XSS. Recommended para sa SPAs.
  • localStorage — Accessible ng JavaScript. Vulnerable sa XSS. Iwasan kung maaari.
Warning "Ang localStorage ay madaling nakawin kung may XSS vulnerability. Kung kailangan mo talaga gamitin, i-expire agad ang token at huwag maglagay ng sensitive data."

Password Reset Flow

Ang Laravel ay may built-in na password reset functionality:

// routes/api.php
Route::post('/forgot-password', [PasswordResetController::class, 'sendResetLink']);
Route::post('/reset-password', [PasswordResetController::class, 'reset']);

Flow:

  1. User nag-submit ng email sa /forgot-password
  2. Laravel nag-generate ng reset token at nag-email ng link
  3. User nag-click ng link at nag-submit ng new password
  4. Na-update ang password sa database

Summary

  • Ang Laravel ay gumagamit ng bcrypt para sa password hashing
  • Ang JWT ay self-contained tokens; opaque tokens ay naka-store sa database
  • Mas secure ang httpOnly cookies kaysa localStorage para sa tokens
  • Ang password reset flow ay nangangailangan ng email notification
  • Gamitin si AI para i-implement ang password reset endpoints
