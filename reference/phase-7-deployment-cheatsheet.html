Phase 7: Deployment, DevOps & Maintenance — Cheatsheet

Isang mabilis na reference para sa deployment, database management, at maintenance ng Laravel + Next.js app.

Pre-Deployment Checklist

Category Item Status
Environment APP_ENV=production at APP_DEBUG=false ☐
Naka-set ang database credentials at SSL ☐
Naka-configure ang mail driver (SMTP) ☐
Naka-generate ang APP_KEY ☐
Assets Na-compile ang assets (npm run build) ☐
Naka-optimize ang images at fonts ☐
Naka-enable ang gzip/brotli compression ☐
Database Na-backup ang database bago mag-migrate ☐
Na-run ang migrations sa staging environment ☐
May rollback plan kung mag-fail ☐
Naka-setup ang automated backups (cron) ☐
Security SSL certificate naka-install at nagre-renew ☐
Naka-lock down ang .env file permissions ☐

Nginx Configuration Template (Laravel)

server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name example.com;

    root /var/www/myapp/public;
    index index.php;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header X-XSS-Protection "1; mode=block";

    charset utf-8;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    error_page 404 /index.php;

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_read_timeout 300;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }

    # Cache static assets
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff|woff2|ttf|svg)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

Vercel Deployment Steps (Next.js)

1

Mag-sign up sa vercel.com gamit ang GitHub account.

2

I-click ang "Add New Project" at piliin ang repository.

3

I-set ang Environment Variables sa Vercel dashboard (Settings > Environment Variables).

4

I-click ang "Deploy". Awtomatikong magbu-build at magde-deploy ang Vercel.

5

Para sa custom domain: Settings > Domains > i-add ang domain at i-update ang DNS.

Tip Sa bawat push sa main branch, auto-deploy ang Vercel. Sa bawat branch, may preview deployment na may unique URL.

Docker Basics para sa Next.js

# Dockerfile — multi-stage build
FROM node:20-alpine AS base

# Dependencies
FROM base AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --only=production

# Build
FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

# Production runner
FROM base AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs
EXPOSE 3000
ENV PORT=3000
CMD ["node", "server.js"]
# docker-compose.yml
version: "3.8"
services:
  nextjs:
    build: .
    ports:
      - "3000:3000"
    env_file:
      - .env.production
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "wget", "--spider", "http://localhost:3000"]
      interval: 30s
      timeout: 10s
      retries: 3

MySQL Backup Strategies

Strategy Frequency Retention Storage
Daily full backup Araw-araw 7-30 days Local disk + S3
Weekly full backup Linggo-linggo 1-3 months Remote server
Monthly archive Buwan-buwan 1 year+ Cold storage (Glacier) 
#!/bin/bash
# Automated MySQL backup script
DB_USER="root"
DB_PASS="password"
DB_NAME="myapp_db"
BACKUP_DIR="/var/backups/mysql"
RETENTION_DAYS=7
DATE=$(date +%F)

mkdir -p "$BACKUP_DIR"

# Backup at compress
mysqldump -u "$DB_USER" -p"$DB_PASS" "$DB_NAME" | \
  gzip > "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz"

# I-delete ang luma sa 7 araw
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +$RETENTION_DAYS -delete

# I-log
echo "[$(date)] Backup completed: ${DB_NAME}_${DATE}.sql.gz" >> "$BACKUP_DIR/backup.log"

# Upload sa S3 (optional)
# aws s3 cp "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz" s3://myapp-backups/
# Cron job — every day at 2 AM
0 2 * * * /usr/local/bin/backup-mysql.sh

Summary

  • Gamitin ang pre-deployment checklist para hindi makalimot ng mahahalagang steps.
  • I-configure ang Nginx na may SSL, security headers, at static asset caching.
  • Para sa Next.js, Vercel ang pinakamadali; Docker naman para sa self-hosting.
  • I-setup ang automated MySQL backups na may retention policy.
  • Gamitin ang monitoring tools (UptimeRobot, Laravel Pulse, Sentry) para bantayan ang app.
  • Regular na mag-update ng dependencies at mag-improve base sa user feedback.
